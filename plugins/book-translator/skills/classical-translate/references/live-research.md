# 实时研究、独立候选与择优

这是每次古译今任务必须执行的宿主调度流程。程序负责保存来源、校验引用和绑定稿件版本，实际搜索、阅读与判断由真实 sub-agent 完成；没有一个脚本能替代这些调用。只提供工作流规则时不要额外安排古文演示；只有收到用户待译的实际内容后才开始本流程。

## 1. 接收实际内容即启动

保留用户原文，清点全部章节/片段。以实际 job、chapter、segment 和原文建立研究任务，不以开发样例、历史成品或预制 source_checks 代替。无需先询问预算或让用户准备检索资料，默认质量优先。明确缺失的原文/文件可以索取；已明确的任务直接执行。

检查本地文件、联网检索与宿主 sub-agent 工具可用。缺少其中必要能力，记录具体未执行的步骤；不得由主 agent 写多个角色名，或用另开用户聊天冒充 sub-agent。默认继承用户当前模型，不为省钱换成更便宜模型，不擅自开通额外付费服务或改变用户模型选择。

## 2. 每章两路独立研究

对完整原文建立问题清单，每项指明触发文字、segment、问题类型和所需证据。

- **原典/古注研究者**：查本段出处、底本、完整上下文、所引诗文或故事原篇、相关古注。读出原典作者/注家真正说了什么及适用语境。
- **反证/异说研究者**：先不读第一人的解释，独立定位原文和相关古注；查可能推翻直观译法的句读、古义、异文、用典变用及不同注家。能访问图版时优先核图；不能核图则明确数字转录层级。

两者必须是宿主返回的不同 agent 实例；短章也保留两路。根据难点增派训诂、经学用典、版本、制度等专题研究者，不以固定源数量或检索次数截断。各自先提交独立记录，再交换证据处理冲突。同一批研究者可串行负责多章，但每章都须有实际覆盖与任务记录；不得假称同时在多个容量槽工作。

实际搜索之后必须打开原籍/古注读相关连续上下文；网页命中或搜索摘要仅是线索。已有可靠电子古籍/扫描件可作为实读对象，不强迫把每条证据都重新下载；但缓存不能替代本次阅读与版本核对。恢复同一作业可保留已有实读证据，恢复 agent 必须重新读与当前问题有关的正文。来自其他作业的材料只作线索，本次实际重读后才能采用。

主 agent 记录全部内容的核查范围；没有典故的句子也需核对古义/句读，不因未列出难点而整段跳过。来源不足时持续换检索词、同篇关联段落、可访问图版、其他古注或正规馆藏资源，记录同源转载关系。没有异说不编造异说，两个 URL 不算两个独立版本。

## 3. 独立双稿，按证据择优

主 agent 核看两路研究实迹、来源内容、覆盖和未决问题，再串行调用 record-source 并固定当前 profile/packet。不要把“文件存在”当成完成研究。

每章派出两名独立 translator，给予相同的完整输入、当前来源与读者要求。两者先独立通读所用原典，再各自完整翻译并写详注；独立初稿完成前不得看另一稿，不能仅把另一稿改写一遍。研究者不能兼任这两名译者。每名 translator 只写其专属候选文件；两稿完成后，登记的主译者读取另一稿、逐段择优，写唯一正式 translation.json。第二译者不写正式稿或审核报告。

协调者分配独立路径，例如 job/research/<chapter>/candidates/a.json 与 b.json；候选内容使用正式译稿结构，绑定实际 translator_id、chapter、packet input_digest，覆盖本章全部 segments。这些是内部候选，不直接交给 finalize；不能用主稿身份签署另一人的候选。

主译者另写 selection.md：逐段记录采用哪一候选、保留或改动哪些字句/详注、原典依据、重要舍弃意见及原因。两稿同解也核对支持关系；不用多数票替代证据。二稿均不足时再研究、请求新候选或重译，不为快速合并拼接不相容的解释。经查仍有合理异说，则明确正文取舍并在注释中保留，不强行裁成唯一正确。

## 4. 动态查证与完整复审

译者和 reviewer 发现新典故、疑义、错引或证据冲突时，立即向协调者提交具体原句、segment、问题与所需核查；由协调者继续派发或唤醒 research worker。协调者独占 sources/profile 的写入，先暂停受影响写入，再合并当前批新增来源并取得新 packet。现有 sources 集合为全局摘要的一部分：任何新增来源都使全部旧稿输入摘要过期，必须通知各章重新核对；不能偷偷更新摘要或复用过期批准。

专属章节 reviewer 与研究者、两名译者为不同实例。它全文对照正式译文与详注，独立再打开所引原典，核读两份候选及 selection.md、研究任务轨迹。检查双稿是否真正独立、舍弃的异说是否有充分理由，不能只看“已完成”标记。缺轨迹、遗漏研究、未经核实的新解释均返回 revise。

全局 reviewer 是未参与任何研究、候选翻译、择优或章节复核的新实例；独立完整核对原文、正式译文、详注、所有引用来源及调度/取舍记录。不能只读章节批准或凭抽样声称全文通过。保留现有 assign/assign-global、coverage、source_checks 和版本门禁。

## 5. 调度记录与运行约束

协调者在 job/research/dispatch.md 记录以下事实，研究者在各自目录写证据，避免并发覆盖：

- job/原文摘要、chapter/segment 覆盖，问题及触发原句；每批的 profile/packet 输入版本。
- 宿主实际返回的 agent ID/任务名、角色、任务范围和实际启动/完成情况；工具调用/输出的可定位轨迹或会话引用。
- 实际搜索词、打开的来源及所读范围、获得的证据位置、未找到或被拒绝的来源；访问失败不可标成已读。
- 两路研究的独立结论、分歧和补查结果；两份候选路径、版本、身份及 selection.md。
- 未决问题、返回谁处理、依据何新证据关闭、受影响稿件和重审范围。

该记录是可审查的过程证据，不能靠任意填写 JSON/Markdown 证明真实性。协调者和 reviewer 必须能对照真实宿主调用及实际读到的内容；缺失时即使 check-chapter/check-global 的结构检查通过，也不得宣布完成或运行最终交付。

按宿主容量分批：研究完成并释放运行槽后启动译者，再启动章节 reviewer；章节之间可交错并行，协调者应定期汇报实质进展。容量不足只改变并发数量，不合并独立角色。长书分批完整读取，保存连续进度，不能以压缩摘要或抽查替代全文。

## 6. 以质量条件结束

古译今没有预设的三轮返工、来源条数、候选稿次数、注释总字数或内部调用预算上限。每条注释 4,000 字符等格式限制通过分条组织解决，不能删除必要解释。只在全部内容覆盖、实际证据支持译文和注释、有效异说公开、两级独立复核无未解决实质问题且版本匹配时交付。

“不考虑时间和花费”意味着不以节约为由减配，不意味着捏造证据或无意义重复。若新一轮没有新增证据或思路，应换检索路径、查不同古注/版本、换独立 worker，而不是机械循环。真实访问/材料/权限障碍经可行替代仍无法解决，或者宿主额度/上下文限制实际中断，则保存具体未完成项与恢复入口；没有可解路径时如实报告，不能降低标准假装完成。
