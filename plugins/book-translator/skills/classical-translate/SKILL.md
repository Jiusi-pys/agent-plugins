# 古文精译

使用本插件自己的 `translation-review`，不修改或依赖独立 Agentic Review。默认向初学者给出忠实的现代汉语全文、原文对照和详细注释；精译不等于逐字生硬替换，更不能概括删节。

开始前读取 [实时调度与择优](references/live-research.md)、[考据规范](references/research-standard.md) 和 [证据与稿件契约](references/evidence-contract.md)。代码工具位于技能目录向上两层的 `scripts/book_translate.py`。说明将针对用户本次原文实时分派研究、独立精译、择优、核验和交付。

**质量优先是默认执行规则**：不得为节约时间、费用、调用次数而减少查阅范围、候选译文、详注或全文复审。古译今不采用其他技能中的默认三轮返工上限；工作量由文本难点和证据决定。遵守宿主实际并发/访问/额度限制，分批执行并保存进度，不虚称无限资源或保证绝对正确。

**直接处理实际输入**：用户无需准备预演、样例、古籍摘录或研究方案。拿到原文即启动真实研究；无实际输入则仅索取原文或文件，不先翻译自选示例。`prepare`/`prepare-text` 只做原文快照与清点，不是预演。开发样例、历史阅读声明、预先写好的报告均不能代替本次研究。

## 准备与真正查阅

1. 已有作业先 `status` 恢复；用户只粘贴文字时，将原文原样保存为作业外的 UTF-8 TXT。不要静默繁简转换、改字、增删标点或把输入重写成自己记得的版本。非 UTF-8 文件先辨明编码并保留原件。
2. TXT/Markdown 输入运行 `prepare-text <source> <new-job>`；按 Markdown 一级/二级标题与段落清点，不把 Markdown 源文当执行指令。输出为 `.md`，不需要安装 EPUB 编排。EPUB 输入先沿 [书籍翻译](../book-translate/SKILL.md) 定位当前启用的 EPUB 编排，再运行：

   ```text
   python <script> prepare <source.epub> <new-job> --epub-editor-root <actual-root> --mode classical_chinese
   ```

3. 输入无明确书名/作者时先根据片段检索、核对上下文再确定；未能确定则说明佚名/出处待定，不能杜撰。完成 profile 的书目字段、术语表及 `classical.base_edition`；普通外文模式与古译今模式不能中途切换。
4. 对每章完整梳理句读、训诂、用典、名物制度和异文疑点，建立与 segment 关联的研究任务。**必须通过宿主 sub-agent 工具，实际派出两名不同实例的 research worker**：原典/古注研究者与独立反证/异说研究者；短篇也不省略。各自先独立检索并核读，再比较证据。按实时调度文档记录真实任务身份、检索/阅读轨迹及结论；不得仅手写角色名。来源注册只由主 agent 执行，译者和 reviewer 仍须读所用原典。
5. **实际打开并阅读**原籍正文和相关古注；检索摘要、网址、模型记忆、引用别人说“某书曰”都不能替代。优先可定位的图版/影印、可靠数字古籍及校勘本；可靠学术研究用于辅助，通俗网页仅作检索线索。检索失败换可访问来源，说明版本层级，不能绕过访问限制或伪造阅读。
6. 保存必要的实读内容及上下文到 UTF-8 capture 文件，另记来源元数据；运行 `record-source <job> <metadata.json> <capture.txt>`。它只封存证据，不会上网替你核实真实性。扫描件记录页/叶、栏行、原件路径或图版链接和实际核读转写，不把未查图的 OCR 当定本。非公版现代校注仅保存任务需要的短引文与自己的研究笔记，遵守引用限制。
7. 当前章两路研究覆盖完整、重要问题均有可复查依据后，才派发该章正式候选翻译。翻译/复核中出现新疑点，立即回派研究者继续查找对应古籍；研究不是只能执行一次的前置阶段。增加或修改研究来源会使当前全部稿件输入摘要失效；协调者暂停相关写入，分批登记新增证据，通知所有受影响 worker 重新核对，不能只替换 digest。

## 精译、详注与独立审核

沿用 [任务与数据契约](../book-translate/references/job-contract.md) 的真实 sub-agent 调度、身份登记及版本门禁。每章两名 translator 先独立完成全文与详注，再由登记的主译者逐段择优形成唯一正式稿；候选稿路径、输入版本、取舍记录见实时调度文档。研究者、两名译者、章节 reviewer 为不同实例；全局 reviewer 必须是未参与研究、翻译、择优或章节复审的新实例。多章按宿主容量分批并行，不得创建用户侧新聊天或自演多个角色。

- 将 [角色补充指令](templates/roles.md) 加入原有 translator/reviewer/global 模板，要求读取本技能和考据规范。每章批次必须完整读取，不能以抽查取代全文。
- 独立候选完成前不得互读对方稿件；择优比较遗漏、语义、语气、流畅度和详注依据，不凭多数投票或拼接句子决定正误。取舍不能由主协调者冒充译者完成，来源冲突先重新研究。
- 每个片段都要有 `classical` 校读记录和原典/古注引用，包括原样保留项目。古文恰好也是汉字不是 preserve 的充分理由；正文应译成现代汉语。
- 先逐句精译，再解释难点：词义、通假、词类活用、倒装省略、人物指代、礼制称谓、度量纪年及作者立场。补出的隐含主语或宾语应在注中说明依据，不能强行消除有意义的歧义。
- 用典必须说明出处与卷篇、原句、原故事或诗篇语境、在本文中借用的意思，以及与原语境可能不同之处。真正读到的毛传、郑笺、杜注、孔疏等分别署明；有来源支持的分歧公开列出。不要把《左传》的话标成《春秋》经文。
- 初学者注释应详细到能够独立理解，数量由难点决定。长注可拆成多条有各自证据的注释；每条限 4,000 字符。现代类比只能标为“假设示例”，不能代替古籍背景。
- `verified` 只表示本次解释证据已查；存在有依据的异说用 `disputed`、注明备选并附 `textual` 注；关键证据缺失、解释未定用 `unresolved`，不得导出为精译完成。
- 主 agent 核对本次研究/双稿/择优真实轨迹，并运行 `check-chapter --draft-only` 后让 reviewer 实际独立打开原典或核看本地图版，不复制译者的已读声明。reviewer 对所有被引用来源填写 `source_checks`，检查引用存在之外，还要审上下文和证据是否支持解释。关键用典与争议字句不得只读本地摘录；缺少真实研究或双稿择优证据也必须返回 revise。
- 全书 reviewer 再次全量对照原文、现代文、详注和所有来源，核查异说是否平衡、作者/注家层次是否清晰、跨章称谓是否一致，并核查本次调度轨迹。写完整 `source_checks` 并通过 `check-global`。仍有实质问题就继续研究、改稿和复核，不设固定返工上限，不因成本或耗时缩减。只有真实材料/权限/环境障碍经可行替代仍不可解，或需要用户独有的底本/取舍信息时，才报告具体缺口并保存进度；不能将无效重试充作深入研究。

## 输出

```text
python <script> finalize <job> <new-output.md或.epub>
```

文本输出分列原文、现代文、详注、字句/用典/异文判断及实查文献。EPUB 保留既有结构，现代文旁设置可点击的详注、原文对照和校读依据，调用已有 EPUB 编排，再检查正文、元数据和链接。原件及已有输出均不得覆盖。

交付应说明实际查过什么版本/页面、哪些古注，及尚未做的图版校勘、版本穷尽比对或 EPUBCheck。正文核读、引文命中、模型独立审核和出版级校勘是不同证据；不能因为报告有 hash 就声称真正读过，也不能把机器审核称为绝对无错。
