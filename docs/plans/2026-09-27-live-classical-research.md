# 古译今实时研究与质量优先：0.2.1 方案

用户明确要求收到真实古文后实时调动 sub-agent 寻找对应古籍、翻译和详注；不需要预先准备示例或预演，不因时间与花费减少质量工作。

## 本轮范围

修改插件技能的执行规则和角色模板，不改变 Python 数据结构、既有来源/译稿/审核门禁及 EPUB 适配器。协调与联网能力由宿主工具提供，不能声称 Python 检查器能证明已调用真实 agent。既有古文样本仅保留为历史开发记录，本轮不再运行样本翻译。

## 执行设计

1. 用户给出实际原文即进入任务；prepare 仅快照与清点，不生成试译书、示例预演或要求用户整理研究资料。
2. 每章至少两名不同实例的 research worker：原典与古注研究、独立反证与异说研究。分别先独立查阅；使用宿主真实 sub-agent 工具。每个难点建立对应 segment、问题、实际 agent、检索/阅读轨迹、所得证据、冲突和处理结果的记录。没有实时研究证据，不派发该章正式翻译或交付。
3. 每章两名不同实例的 translator 独立完成全文候选译文与详注。第二候选先不读第一候选，写独立临时文件；登记的主译者在两稿完成后逐段择优形成唯一 translation.json，记录取舍。任何新解释均回查来源；意见相同不等于正确，意见不同则扩展检索。
4. 专属章节 reviewer 与研究者、两名译者均分离；全局 reviewer 也是未参与研究、翻译和章节复审的新实例。全量核原文、注释、典故、独立研究轨迹及择优过程，保留现有 source_checks/coverage/digest 校验。
5. 研究、翻译、复核之间允许随新问题回派 research worker。每批来源登记后产生一致候选版本，新增来源/改稿按既有全局摘要规则重审，不只改摘要。宿主并发不足按阶段排队，所有角色独立身份不变。
6. 古译今取消固定三轮返工，不限制内部查证/候选次数、注释总量或检索来源数量，也不以省钱省时缩减全文核验。单条注释长度等技术限制通过拆分处理。完成由覆盖、证据支持、公开有据异说和全部实质问题闭环决定。遇到真实访问/额度/会话限制保存进度和具体缺口，不绕过限制或冒报完成；可行的替代检索继续，不以反复无效重试充数。

## 方案审核

主 agent 自审，不冒称独立设计评审。核对了三种反例：其一，新建多个角色名但没有调用工具，要求保留宿主返回身份和实际任务轨迹；其二，两个网站转载同一文本或两名译者同意即当作证据，要求记录同源性、原文核对及实质取舍；其三，研究新增证据破坏正在运行的译稿摘要，要求由协调者串行登记并通知所有受影响 worker 重核。

## 验证

本轮仅修改 Markdown/YAML 提示规则与版本，无新增程序逻辑，不编写只匹配指令措辞的测试。检查跨技能的三轮限制不再套用古译今；校验技能/manifest、既有 50 项插件回归与隔离安装，检查安装后的新引用可达，打包后检查路径及完整性。用 Plugin Creator 更新同一插件至 0.2.1 并读回所有改动；不对新流程作尚未执行的真实书籍运行证明。
