# 古译今实时研究 0.2.1 验收

本轮响应用户对古译今流程的明确要求：真实原文到达后实时调动 sub-agent 查古籍、精译和详注，不需预演，不因时间或花费缩减工作。方案见 [实施与自审方案](../plans/2026-09-27-live-classical-research.md)。

## 执行规则变更

- 两路独立 research worker 从实际原文分别查原典/古注与反证/异说；记录宿主真实任务身份、逐项原文问题、实际搜索和阅读轨迹。
- 两名不同实例的译者先独立完成本章全文与详注，主译者随后逐段择优形成唯一正式稿，保留两份候选及取舍依据。
- 研究者、两名译者和章节 reviewer 相互独立，全局 reviewer 为未参与前序工作的另一新实例；两级审核还要核对真实研究与择优过程。
- 翻译/审核发现疑点可随时回派研究；来源变化按现有全局输入摘要规则通知所有受影响章节重新核对候选、稿件和审核。
- 古译今取消默认三轮上限，不以耗时、费用、固定来源或候选数量降低精译深度。实际并发/访问/额度限制仍需遵守；真实障碍保留可恢复状态，不能机械无效重试或虚称完成。
- 正常任务不运行开发样例或自选古文演示。原有历史开发证据保留，不当作新任务的研究记录。

## 明确边界

本轮没有用户待译原文，不启动古文演示或预演，也不声称新双路研究/双稿流程已经通过真实书籍运行。本次通过的是规则一致性、现有程序回归、安装与发布读回。

真实 sub-agent 调度由宿主按技能执行，Python 的引文/身份/摘要门禁不等于阅读证明，也不解析调度及择优 Markdown。协调者和 reviewer 必须对照实际宿主调用；缺过程证据即使结构检查通过也不能交付。此限制已写入执行规范。

没有修改用户全局 marketplace 配置。本验收记录生成时尚未 Git 提交或推送，改动位于 codex/book-translator 工作区；后续提交与推送状态以实际 Git 记录为准。
