# WeRead 导出器：三项审查问题的 TDD 修复

本次仅处理独立审查发现的三个 P2：未到书末误报成功、纯 ASCII 正文丢失、按全书图片 URL 去重导致后续引用丢失。没有使用真实网站账号，测试通过 Playwright 拦截请求提供本地阅读器页面。

## 先失败

修改实现前新增 5 个回归测试方法，实际运行全部 18 项。旧 13 项仍通过，新增路径发生 8 次断言失败（含子场景），日志为 `.local/weread-review-fixes/red.log`：

- 未完成会话返回成功值、发布/替换合并书籍的路径。
- 可见 Canvas 已捕获 `OpenAI`、`12345`、公式及整句英文，却在输出过滤时丢失。
- 同一插图在两个连续正文页和两个章节出现时，后续引用丢失。
- 同一次捕获中重复观察同一图片位置，输出多余引用。

## 实现与通过条件

- `main` 仅在 `reached_end=True` 后合并全书。无完整章节进展且未确认书末时返回 1；保留章节片段及原始记录，已有完整合并文件不被覆盖。CLI 传播该退出码。
- 删除基于字符类别的正文过滤；测量画布继续由已有可见 Canvas 选择逻辑排除。
- 删除贯穿全书、恢复会话的 URL 集合。单次页面组块按 URL 加图片位置去除重复观察；每次正文出现保留独立引用。会话通过最近的页面快照识别相同页面的重复捕获，章节切换时重置。
- `build_page_blocks` 和 `run_session` 内部调用移除全书图片去重参数。原测试只同步调用签名，正文、链接和 UTF-8 断言保留。

首次修复后 18 项全部通过，原始日志为 `.local/weread-review-fixes/green.log`。浏览器测试同时覆盖同一图片出现两次和末页连续停滞，确保两条图片引用均保留、重复捕获不增加引用。ASCII 测试使用真实 Chromium `fillText`，并验证离屏英文辅助画布仍被排除。

## 独立复审反例与第二轮 TDD

独立审查者重跑 18 项通过，同时用离线 Chromium 发现新停滞判断会遗漏“正文加图 → 仅同图 → 新正文”中的纯图片页。第一轮复审因此未通过。

先加入三页回归，并扩展到中间页与首屏正文、图片完全相同的场景；普通启动、点击当前目录不重绘、从其他章节跳回开头三条路径共 6 个子场景全部先失败，见 `.local/weread-review-fixes/review-red.log`。

随后在可见 Canvas 快照中加入真实绘制修订号：`fillText` 与整幅 `clearRect` 更新修订号，清空导出器内部缓存不会更新。停滞判断现在同时核对渲染变化，实际清空/重绘的纯图片页和相同正文页均被保留；没有重绘的停滞仍被识别。修复后完整 **19 项测试全部通过**（24.357 秒），见 `.local/weread-review-fixes/review-green.log`，`git diff --check` 通过。

第二轮由同一位独立审查者完成，未发现新的可操作问题；原三个缺陷及首轮复审新增问题在已复现的场景中均已关闭。审查者独立运行完整 19 项测试全部通过（25.233 秒），范围内 `git diff --check` 通过；内存反向验证仅移除快照中的绘制修订号，新增 6 个子场景全部重新失败（图片引用数量 `1 != 2`），确认回归能捕获缺陷。审查涵盖相关未暂存修改和未跟踪复审记录，暂存区为空，未修改仓库文件。

上述修复和独立复审阶段未重跑全仓测试。后续按用户要求在 US 运行插件全仓：287 项发现、279 通过、8 引擎测试跳过、0 失败/错误；WeRead 19 项全部通过（38.888 秒）。8 项引擎测试在 Windows 用真实引擎补跑全部通过。完整结果及逐项跳过原因见 [US 全仓回归记录](2026-10-11-plugin-us-full-suite.md)。未访问真实网站账号；不将离线 Chromium 模拟阅读器验证表述为真实账号网站及全部渲染方式验收。
